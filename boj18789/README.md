# BOJ 18789 "814 - 2" 탐색기

8×14 표에 숫자를 채워, 1부터 X까지의 수가 모두 읽히게 하는 문제다. 이 폴더에는 그런 표를 찾는 프로그램과 지금까지 찾은 가장 좋은 표가 들어 있다.

지금까지 찾은 가장 좋은 표는 `best_X10018.txt`이고 점수는 10018이다. `verify.py`로 다시 채점해서 확인했다. 목표로 잡았던 14000과 1등 기록 16361에는 이르지 못했다.

## 파일

| 파일 | 내용 |
|---|---|
| `sa5.cpp` | 담금질 기법 탐색기. 코어 하나만 쓴다. 아래 실험은 대부분 이 프로그램으로 했다. |
| `sa6.cpp` | `sa5.cpp`에 실험용 기능 세 가지를 더한 것이다. 기능은 아래 "sa6의 추가 기능"에 적었다. |
| `pt.cpp` | 온도가 서로 다른 표 여러 개를 동시에 탐색하고, 일정 횟수마다 이웃한 온도끼리 표를 맞바꾸는 프로그램이다. 이 방식을 parallel tempering이라고 한다. OpenMP로 여러 코어를 쓴다. |
| `verify.py` | 채점기. 표 파일을 읽어 점수 X를 출력한다. 탐색기와 계산을 공유하지 않고 문제 정의대로 한 수씩 확인한다. |
| `best_X10018.txt` | 점수 10018인 표. |

## 빌드와 실행

```bash
g++ -O3 -march=native -o sa5 sa5.cpp
g++ -O3 -march=native -o sa6 sa6.cpp
g++ -O3 -march=native -fopenmp -o pt pt.cpp

python3 verify.py best_X10018.txt     # 10018 출력
```

`sa5`와 `sa6`의 인자는 순서대로 다음과 같다.

```
./sa5 T seed secsA t0 t1 secsTot step init out
```

| 인자 | 뜻 |
|---|---|
| `T` | 목표값. 1부터 T까지 모두 읽히는 표를 찾는다. |
| `seed` | 난수 seed. |
| `secsA`, `t0`, `t1` | 처음 `secsA`초 동안 온도를 `t0`에서 `t1`로 낮춘다. 그 뒤에는 `t1`에 머문다. 온도는 표를 나쁘게 만드는 변경을 받아들일 확률을 정하는 값이고, 식은 아래 "탐색기가 하는 일"에 있다. |
| `secsTot` | 전체 실행 시간. 단위는 초다. |
| `step` | 목표를 이뤘을 때 목표값을 얼마나 올릴지 정한다. 0이면 목표를 이룬 즉시 끝낸다. |
| `init` | 시작할 표 파일. `-`를 주면 무작위 표에서 시작한다. |
| `out` | 결과 파일 이름의 앞부분. |

결과 파일은 두 개다. `out_s<seed>.txt`에는 목표를 이룬 표 가운데 실제 점수가 가장 높은 표가 들어간다. `out_s<seed>_last.txt`에는 읽히지 않는 수의 개수가 가장 적었던 표가 들어간다.

```bash
# 무작위 표에서 시작해 1~9999를 목표로 2분 동안 탐색한다
./sa5 9999 1 60 2.0 0.4 120 0 - out

# 저장된 표에서 시작해, 목표를 이룰 때마다 목표값을 100씩 올린다
./sa5 10099 1 1 0.45 0.45 3600 100 best_X10018.txt esc
```

`sa5`는 코어 하나만 쓰므로, 코어가 여러 개면 seed를 바꿔 프로세스를 코어 수만큼 띄운다.

`pt`의 인자는 다음과 같다. `nrep`은 동시에 탐색할 표의 수이고, 온도는 `tmin`부터 `tmax`까지 같은 비율로 벌려 놓는다. `chunk`는 표를 맞바꾸기 전에 표 하나가 시도하는 변경 횟수다.

```
./pt T0 seed nrep tmin tmax secs step chunk init out [qc] [mcap] [threads]
```

### sa6의 추가 기능

- 컴파일할 때 `-DRR=8 -DCC=13`처럼 표의 크기를 바꿀 수 있다.
- 환경변수 `ALLSTR=1`을 주면 0으로 시작하는 문자열까지, 곧 0000부터 9999까지 문자열 10,000개가 모두 읽히기를 요구한다.
- 환경변수 `FREEZE=1`을 주면 시작 표 파일에 숫자로 적힌 칸은 바꾸지 않고, `.`으로 적힌 칸만 바꾼다.

## 탐색기가 하는 일

탐색기는 칸 하나를 골라 숫자를 다른 숫자로 바꿔 본다. 그리고 T 이하의 수 가운데 읽히지 않는 수가 몇 개인지를 바꾸기 전과 견준다. 개수가 줄거나 같으면 바꾼 표를 받아들인다. 개수가 d개 늘면 exp(-d/온도)의 확률로만 받아들인다. 코드에서는 이 개수를 `E`라는 변수에 담는다. `E`가 0이 되면 1부터 T까지가 모두 읽힌다.

`E`를 매번 처음부터 세면 느리므로 다음과 같이 센다. 인접한 칸을 따라 4칸을 차례로 지나는 길을 경로라고 하자. 같은 칸을 다시 지나도 된다. 방향을 구분하지 않으면 8×14 표에는 경로가 20,220개 있다. 탐색기는 경로마다 지금 읽히는 4자리 문자열을 저장하고, 문자열마다 그 문자열을 읽는 경로가 몇 개인지를 센다. 경로를 거꾸로 따라가면 뒤집힌 문자열이 읽히므로, 문자열과 그것을 뒤집은 문자열은 한 묶음으로 센다. 칸 하나를 바꾸면 그 칸을 지나는 경로만 다시 계산하면 된다. 표 한가운데의 칸은 경로 약 950개에 들어 있고, 가장자리에 가까운 칸은 그보다 적은 경로에 들어 있다.

5자리 수 1abcd는 1이 적힌 칸에서 출발해 이웃 칸으로 간 다음 abcd를 읽어야 한다. 그래서 탐색기는 이웃에 1이 있는 칸에서 출발하는 경로만 따로 세어, 10000 이상의 수가 읽히는지를 판정한다.

변경 시도의 대부분은 버려지므로, 버릴 변경을 빨리 알아내는 것이 속도를 좌우한다. 탐색기는 읽히지 않는 수마다, 어느 칸을 어느 숫자로 바꾸면 그 수가 새로 읽힐 수 있는지를 미리 찾는다. 그리고 칸과 숫자의 조합마다, 그렇게 바꿨을 때 새로 읽힐 수 있는 수가 몇 개인지를 세어 둔다. 어떤 변경으로 실제로 새로 읽히게 되는 수의 개수는 이렇게 세어 둔 값을 넘지 못한다. 변경 때문에 읽히지 않게 되는 수가 이 값보다 많아지면, 탐색기는 나머지 경로를 보지 않고 그 변경을 버린다. 목표값이 10999일 때 직접 재 보니 시도의 97%가 이렇게 일찍 끝났고, 코어 하나에서 1초에 약 110만 번 시도했다.

## 직접 돌려 본 결과

모두 Xeon 2.1GHz 4코어 머신에서 돌렸다. 각 줄은 seed 하나로 한 번만 돌린 결과라서, seed를 바꾸면 값이 달라질 수 있다.

무작위 표에서 시작한 결과는 다음과 같다. 9999 행은 `sa5` 바로 앞 판으로 돌렸고, 나머지는 `sa5`로 돌렸다. 목표값이 9999 이하이면 두 판은 같은 계산을 한다.

| 목표값 T | 실행 시간 | 읽히지 않는 수의 개수가 가장 적었을 때 |
|---|---|---|
| 9999 | 32초 | 0개 |
| 10999 | 60초 | 1개 |
| 11999 | 5분 | 7개 |
| 12999 | 5분 | 17개 |
| 13999 | 5분 | 33개 |
| 15999 | 5분 | 96개 |

5분짜리 실행은 온도를 2.5에서 0.4로 270초 동안 낮추고 나머지 30초는 0.4에 머물렀다. 목표값이 15999일 때는 220초, 230초, 290초 시점에 읽히지 않는 수가 모두 96개여서, 마지막 70초 동안 나아지지 않았다. 실행을 시작해서 230초까지의 시도 가운데 받아들여진 비율은 목표값 15999에서 0.3%였고 목표값 11999에서 1.8%였다. 목표값이 높으면 같은 온도에서 변경이 훨씬 덜 받아들여진다는 뜻이다. 그래서 목표값이 높을 때는 온도를 더 높은 값에서 시작해 더 천천히 낮춰야 할 것으로 보이는데, 이것은 내 추측이고 아직 돌려 보지 않았다.

### 1을 모든 칸 옆에 두는 방법은 안 될 것으로 보인다

10000부터 19999까지를 한꺼번에 읽는 방법을 하나 검토했다. 1abcd는 1 옆의 칸에서 abcd를 읽어야 하므로, 모든 칸의 이웃에 1이 있고 문자열 0000부터 9999까지가 모두 읽히면 10000부터 19999까지가 모두 읽힌다. 다만 그러려면 1을 많이 놓아야 한다. 내 어림으로는 16개에서 20개가 필요한데, 정확히 계산해 보지는 않았다. 그러면 1이 들어가지 않는 문자열을 읽을 칸이 약 94개만 남는다.

칸이 줄어도 문자열 10,000개를 모두 읽을 수 있는지 알아보려고, `sa6`으로 더 작은 표에서 문자열 10,000개를 모두 요구하고 150초씩 돌렸다.

| 표의 크기 | 칸 수 | 읽히지 않는 문자열의 개수가 가장 적었을 때 |
|---|---|---|
| 8×13 | 104 | 15개 |
| 8×12 | 96 | 57개 |
| 8×11 | 88 | 182개 |
| 8×10 | 80 | 392개 |

8×14에서 1000부터 9999까지만 요구했을 때는 32초에 0개가 됐는데, 칸을 8개만 줄여도 150초 안에 0개가 되지 않았다. 그래서 1을 16개 넘게 놓고 남은 칸으로 나머지 문자열을 모두 읽기는 어렵다고 판단했다. 작은 직사각형 표와 1이 군데군데 박힌 표는 같은 조건이 아니므로, 이 판단은 증명이 아니라 추측이다.

### pt.cpp는 아직 효과를 확인하지 못했다

`pt`는 목표값 9999로 60초 동안 한 번만 돌려 봤다. 표 12개를 온도 0.3부터 1.2까지에 두었고, 모두 합쳐 4억 7천만 번 시도했지만 0개가 되지 않았다. 30초 시점에 가장 낮은 온도의 표에서 읽히지 않는 수가 13개였다. `sa5`의 앞 판은 같은 목표값에서 3천8백만 번 시도 만에 0개가 된 적이 있다. 한 번씩만 돌린 결과라서 어느 쪽이 나은지는 아직 모른다.

## 해 보지 않은 것

- 목표를 이룬 표에서 시작해 목표값을 100씩 올려 가는 실행을 시작했지만, 결과를 보기 전에 중단했다. 얼마나 빨리 올라가는지는 아직 모른다.
- 5분보다 긴 실행은 해 보지 않았다.
- 칸 두 개의 숫자를 맞바꾸는 변경은 넣지 않았다. 지금은 칸 하나의 숫자만 바꾼다.
